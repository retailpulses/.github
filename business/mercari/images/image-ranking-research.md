# Mercari 商品图片排序：启发式研究与业务知识候选（非规则）

> **状态：Research / NOT APPROVED** · 2026-11-13 · 知识 Owner：Mercari 业务规则 Owner  
> 来源：[Store-Ops PR #313 的图片模块讨论](https://github.com/retailpulses/store-ops/pull/313#discussion_r4560600755)。该研究从产品设计中提取，以免长期业务知识与单个 MVP 技术范围耦合。它不构成可执行的分类/图片排序规则，也不授权在任一店铺自动覆盖人工决定。

## 研究问题

批量上新时 Giga 的图片原有次序可能不是最佳销售展示次序。需要探索不增加运营负担的建议排序机制，但**当前不具备证明某个固定顺序提升转化率的 A/B 或销售数据**。

## 候选图片角色（仅供研究与人工审核）

| 角色 | 候选识别方式 | 不确定性/风险 |
| --- | --- | --- |
| HERO | 清楚展示完整产品主体，可作首图 | 不同类目主图规范可能不同 |
| ANGLE | 补充产品角度、颜色或外观 | 不能仅凭图像断言规格 |
| DIMENSION | 包含尺寸图、结构示意 | 图片文字/尺寸必须核对来源事实 |
| FEATURE | 说明功能、材料、安装与附属件 | 不得推导未经证实的性能/配件 |
| LIFESTYLE | 生活场景、使用情境 | 场景图可能提供价值，不能仅因是场景图而忽略 |

**候选顺序：** HERO → ANGLE → DIMENSION → FEATURE → LIFESTYLE，仅是待验证的通用启发式；商品类型、真实用户价值和平台规则可能需要不同排序。未能可靠判断时保留供应商原顺序。

## 可测试的后续研究路线（不构成本次产品交付要求）

1. 从具有明确人工接受结果的商品中整理脱敏的 Giga 来源排序、商品类别、最终接受顺序和调整原因（仅经授权且能去敏的数据）。
2. 对不同类目比较人工排序成本、主图选择一致性、排序建议采纳率；不得声称提升销售或 AI 排序效果，除非有对应可复现证据。
3. 优先评估无需 LLM 的规则/元数据启发式；仅当错误率与人工修正成本证明必要时，再试用 Vision/LLM 分类。
4. Agent 建议字段可以是 `suggested_role`、`suggested_rank`、`reason`、`confidence`，均明确为建议，不当作真实商品属性。不可覆写已接受人工排序。
5. 对外部图片大小/格式/来源 URL 的硬性筛选，仍须遵循独立批准的 Mercari 业务规则与官方约束，不由本研究定义。

## 事实与来源边界

- 供应商图片顺序可能不符合运营展示需要：来自 PR #313 的产品问题陈述，**未量化验证**。
- 角色分类与排序：启发式假设，**未批准、未在真实运行中验证**。
- Giga URL、Mercari 单图大小/数量限制、实际操作规则：应追踪 [官方图片说明](https://support.mercari-shops.com/hc/ja/articles/10202904748057) 和公司已批准的规则，不以此研究替代。
- 本研究与 [Store-Ops #312](https://github.com/retailpulses/store-ops/issues/312) 独立；当前 MVP 仅需过滤、选择首图、人工可选排序及已接受决定持久化。

## 未来批准条件

只有产生经实际业务验证的类目适用范围、误判/例外处理、手工覆盖边界、版本与责任 Owner，才能单独提案为正式可执行规则。未经这些证据不推广为组织通用规范。
