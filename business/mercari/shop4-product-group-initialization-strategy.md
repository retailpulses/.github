# Shop4 商品グループ初始化策略

**Owner:** リテルパルス合同会社 / Mercari Operations  
**更新日:** 2026-11-18 JST  
**状态:** 初始化策略；尚未执行线上重组  
**范围:** Shop4 优先；不删除商品、不合并 Item Code、不修改价格或库存。  
**用户确认方向:** 同 SPU1 的变体优先归组；相近类目可考虑；允许取消不合适的现有分组。

操作方法见 [商品グループ管理参考](product-group-management.md)。

## 1. 目标与身份边界

让买家先比较同一产品的颜色、尺寸等变体，再比较用途一致的替代款。覆盖率不是唯一目标，不为了凑满10个而混入无关商品。

- Item Code 对应独立 listing 的业务身份不变；分组只增加选择关系。
- SPU1 使用现有 canonical 身份/已批准规则；不要把 Giga 的 Product Group 选品分类当成 SPU1。
- 仓库 [SPU1 规则](https://github.com/retailpulses/commerce-lab/blob/main/services/canonical-lab/src/product_grouping.py) 支持特定的一字母/三字母末尾变体后缀去除。模式推导只是候选证据，不能把所有代码统一截断。
- 所有分组先满足 Mercari 允许的第三级类目范围和10商品上限。

这些数字用于确定工作重点，不作为直接上传清单。执行前必须重新导出，纳入近期分类、标题和上架更新；候选数量不等于最终可创建组数。

## 3. 分组优先级

| 层级 | 规则 | 处理 |
|---|---|---|
| P1 | 同 SPU1 变体 | 优先补齐；正确旧组沿用ID |
| P2 | 同系列、跨 SPU1 的规格选择 | 核实系列关系，以宽度、容量、配置等清晰区分 |
| P3 | 同用途的相近替代款 | 仅处理剩余适合比较的商品；关注结构、尺寸、价格范围 |
| 独立 | 无合适比较对象或身份未明 | 保持独立，不强行归组 |

同三级类目只是技术条件，不足以证明商业上适合。桌子与椅子、猫爬架与猫砂盆不因同属家具/宠物大类而归组。商品组也不是套装购买或组合优惠。

同 SPU1 超过10个时，按有意义的规格轴拆分，例如尺寸→颜色；不按CSV行号随机切块。已有正确SPU1组不为跨型号分组而拆散。

## 4. 旧组处置标准

| 判断 | 动作 |
|---|---|
| 同SPU1、类目兼容、成员完整、标签清楚 | KEEP，保留 |
| 成员正确但漏变体、顺序不合理、标签重复 | REPAIR，原组修正 |
| 把不同用途/互不相关商品凑组 | UNLINK / REBUILD，取消关联后按P1–P3重建 |
| 同SPU1分散在多个组且没有规格拆分理由 | CONSOLIDATE；选正确旧组为目标，解除其他关联后迁移 |
| 超过10个候选或需合理规格拆组 | SPLIT，保留有意义的分组边界 |
| 孤立单成员组且无可补齐对象 | 可清空关联；确认无用后删除空组 |
| SPU1或类目证据冲突 | HOLD，记录具体冲突，不推断身份 |

**省略名重复本身不构成取消分组的理由。** 例如 N512P193784 的颜色变体均叫「ダイニングチェア」，优先改成真实颜色；TX299554 猫爬架可按已核实信息标注「グレー」「ベージュ」。实际颜色须以最终商品证据为准。

用户允许取消不合适的旧分组；这不要求全量清空519组。优先保留正确关系，减少重建和回滚成本。

## 5. 初始化执行顺序

1. **刷新基线**：保存全量商品、完整旧组配置及批次时间，核对线上近期更新。
2. **逐组判定**：给所有旧组分配 KEEP / REPAIR / REBUILD / CONSOLIDATE / SPLIT / HOLD，写明成员级原因和目标组。
3. **先修分类**：需要分类修改的商品先解除关联，再单独修改并重新导出确认。
4. **完成P1**：补齐、合并或合理拆分同SPU1，优先处理有库存、可售商品；不因缺货自动判定旧组错误。
5. **补P2/P3**：处理剩余商品，给出同用途/系列证据；不强求所有商品归组。
6. **分批执行**：先验证少量完整案例。迁移按旧组解除→回读→目标组建立/更新→回读进行；失败保持可恢复状态。
7. **清理空组**：全部关联迁移确认后，再通过管理画面删除不再使用的空组；清空CSV不等于删除组对象。

稳定且正确的旧组ID优先复用。新ID可采用 shop4_spu_<key>_<part> / shop4_family_<key> 的命名思路，须先验证当前模板允许的字符、长度及唯一性；不是已验证的平台格式。

## 6. 标签与排序

买家选择轴用「カラー」「サイズ・カラー」「タイプ」等准确日文。省略名明确颜色、尺寸或件数，如「幅120cm・ホワイト」；不要重复品类名，也不显示内部SKU。

顺序按规格自然递增，或按经确认的销量/主推款排序；缺少销量证据时不得宣称“畅销款”。相同颜色但件数不同须明确标注。组内规格无法清楚区分时，应重新审视分组。

## 7. 交付与完成条件

每次执行保留：

- 成员级审核表：商品ID、Item Code、SPU1证据、当前/目标组、允许归组类目ID、动作、原因、标签、顺序。
- 独立解除关联CSV与目标组CSV；删除空组的管理画面操作清单。
- before/after、模板版本、执行结果、错误与恢复基线。

完成条件：所有旧组已判定；符合条件的P1已处理或留下具体阻断原因；每个新组<=10个商品且类目兼容；未引入无关商品；标签和顺序回读一致；取消/迁移结果逐项确认；所有listing及价格库存保持预期。P2/P3可以少建，不以100%覆盖作为验收门槛。
