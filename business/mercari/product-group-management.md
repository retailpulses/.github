# Mercari Shops 商品グループ管理参考

**Owner:** リテルパルス合同会社 / Mercari Operations  
**Scope:** 全店；Shop4 优先  
**官方资料核对日:** 2026-11-18 JST  
**性质:** 操作参考；记录本身不执行线上修改。

## 1. 官方来源与边界

- [商品グループ管理機能](https://support.mercari-shops.com/hc/ja/articles/39467798476569)：管理画面操作、法人/Web 限制、三级类目范围、每组最多 10 个商品。
- [商品グループの一括登録・更新](https://support.mercari-shops.com/hc/ja/articles/42646579459993)：专用 CSV、字段及四类操作。
- [普通商品 UPDATE CSV](https://support.mercari-shops.com/hc/ja/articles/60017371839513)：其中分组字段仅供参考，不能借此创建、修改或移除分组。
- [官方 CSV 样例（Mac）](https://guide.mercari-shops-static.com/product_group_import_template_sample.csv)。本次核对了指南字段，未验证样例原始字节；执行时从目标店铺下载当前模板，核对完整表头、顺序和编码。

商品グループ连接多个独立 listing，供买家在详情页切换；不合并商品ID、价格、库存或订单。组内必须属于所选第三级类目配下，不要求叶子类目完全一致。

## 2. CSV 字段

每行描述一个分组。字段如下；实际表头以当前专用模板为准。

| 字段 | 含义 |
|---|---|
| 商品グループ名 | 内部管理名称 |
| 商品カテゴリID | 分组范围的类目ID；不要直接套用商品叶子ID |
| 商品グループID | 未使用的ID创建新组；现有ID更新对应组 |
| 商品画面用タイトル | 买家可见的选择轴，如「カラー」 |
| 商品1_ID ～ 商品10_ID | Mercari 商品ID，按展示顺序排列 |
| 商品1_省略名 ～ 商品10_省略名 | 对应商品的买家可见规格标签 |

内部 Item Code / SPU1 不能替代商品ID。管理用名称、ID不展示给买家；规格标签应使用准确日文，不放内部代码。颜色默认使用标准片假名（如「ホワイト」「ブラック」「ライトグレー」），尽可能与准确的 SKU 種類统一；不得为缩短名称改成「白」「黒」「薄グレー」。共通规则以 [listing-csv-guideline.md 的 BUS-MER-015](listing-csv-guideline.md#customer-facing-color-names-use-katakana-by-default-bus-mer-015) 为准；规格真实性和长度限制仍须核对。

## 3. 创建、更新、解除与删除

| 目标 | 方法 | 输入和结果 |
|---|---|---|
| 创建有商品的新组 | 专用 CSV | 新分组ID、组信息、商品ID与标签 |
| 只创建空组 | 专用 CSV | 新分组ID及组信息；所有商品ID与标签留空 |
| 更新组信息、商品或顺序 | 专用 CSV | 现有分组ID；提交预期的组信息和完整成员列表 |
| 清空该组全部商品关联 | 专用 CSV | 保留现有分组ID和组信息；所有商品ID与标签留空。保留空组，不等于删除组 |
| 移除部分商品 | 管理画面编辑；或完整成员列表更新 | 保留其余成员。CSV 对省略成员的处理应先小批验证，不能假定为追加或局部 patch |
| 删除整个分组 | 管理画面 | 「商品」→「商品グループの管理」→选择目标组→「商品グループを削除する」 |

官方 CSV 指南未提供“删除分组对象”的专用控制字段。不要编造 delete 标志，也不要用普通商品 CSV 的商品删除状态替代解除关联。

### 创建流程

1. 确认目标店铺，导出现有商品与分组资料。
2. 从「商品」→「CSV一括機能」→「商品グループ一括登録・更新」下载模板。
3. 填写新ID、类目、组信息和最多10个商品，上传并核对预览。
4. 执行一括登録・変更，等待历史显示「変更完了」，随后回读核对。

也可在「商品グループの管理」中选择「商品グループを登録」，填写组信息、添加商品及标签后保存。

### 更新流程

沿用现有分组ID，先保存旧状态，再准备完整目标状态；上传预览后核对成员、标签和顺序。管理画面同样支持选择组后「商品グループを変更する」。不要因改名而新建ID，也不要假定空白字段表示不变。

### 移除与重组流程

先区分“移除一个成员”“清空所有关联”“删除整个组”。迁移时先从旧组解除，回读确认，再加入目标组；不要假定跨组自动搬迁。若需改商品分类，先解除关联、单独执行分类修改、重新导出验证，再按正确类目建组；该顺序是公司恢复性操作建议，不把尚未核实的分类锁定条件写成平台事实。

## 4. 公司执行与恢复约定

- 保留变更前的完整组配置及成员ID、标签、顺序，形成 before/after 差异。
- 先小批验证创建、更新、部分移除的实际语义；普通商品 CSV 的数量上限不套用于分组 CSV。
- 分组完成必须同时核对导出状态和买家页面；上传受理不代表成功。
- 失败或结果不明时，先回读再重试；保留错误结果及批次记录。
- 回滚以旧组配置恢复关联；已删除组能否复用原ID须验证，不保证恢复原对象。
- 不得在分组操作中顺带改价格、库存、商品ID或删除 listing。

## 5. 商品グループID 命名规则（SPU1 优先）

**状态：** Sponsor 已确认命名方向（2026-11-18 JST）；适用于新建组。组合、压缩及拆组规则是内部约定，不代表 Mercari 自动识别 SPU1。

### 命名与长度

1. **单一 SPU1：** 直接以完整 SPU1 作为 `商品グループID`，例如 `N510P419618`。保留权威身份的大小写与字符，不从标题或类目猜 SPU1；已有可靠的成员级映射可复用。
2. **多个 SPU1：** 对完整 SPU1 去重、按 ASCII 字典序排序，用下划线 `_` 拼接。例如 `N510P419618_N510P419619`（21 字符）。排序仅用于 ID，不能改变商品展示顺序。跨 SPU1 归组仍需满足类目资格、同系列/同用途及真实可比较规格，不能仅为凑数量合并。
3. **长度预算：** 内部生成上限设为 **30 个 ASCII 字符**，分隔符、摘要及拆组后缀均计入。依据：官方[商品数据导出指南](https://support.mercari-shops.com/hc/ja/articles/11230024110105)明确规定商品グループID查询条件每项最多30字符；这直接证明的是查询限制，当前公开的一括登録指南未另列创建字段的长度/完整字符集限制。不得将查询限制冒充已实测的CSV创建上限。生成器内部限用 `A-Z a-z 0-9 _ -`，以目标店铺当前模板和Seller预览校验为最终依据；如发现更短限制，采用更严格限制并更新此处。
4. **完整拼接超长：** 优先保留完整拼接；确实超过预算时才使用 `可读前缀_H摘要`。摘要为完整规范SPU1列表（排序后，以换行连接，无末尾换行）的UTF-8 SHA-256前10位小写十六进制；可读前缀取完整下划线拼接串的前 `30 - 12 - 拆组后缀长度` 个字符，再去除尾部下划线。单个SPU1超长时采用同一规则。摘要不保证绝对无碰撞，必须检查唯一性；若冲突，扩大摘要长度、相应缩短前缀，仍冲突则保留异常供人工处理，不能静默覆盖。批次映射必须保留完整SPU1集合、完整组合键、最终ID和压缩原因，不能只留截断值。
5. **同一SPU1/组合拆成多个组：** 第一个可用组可用基础ID，后续使用 `_02`、`_03` 等未占用且已登记的后缀；仍在30字符预算内。分组应基于明确的规格/容量边界，分配后保存映射，重跑复用原ID，不按输入行序重新编号。组合键相同也不能绕过每组最多10件限制。

### 唯一性与既有组

- 唯一性检查范围为目标 Shop 的所有现有组（含空组）和当前批次。普通商品导出只能证明其中可见的组，不能证明不存在空组或导出后的新增组；提交前须用最新商品グループ管理数据核对。
- **未占用ID创建新组；已占用ID更新既有组**（官方CSV语义）。如果目标是另建组，基础SPU1已被占用时采用已核实未占用的拆组后缀，不得用新成员列表覆盖旧组。
- 已上线组的ID保持稳定，不为了采用本规范而批量重命名；扩充既有组必须显式采用更新流程并保留完整原成员。若成员SPU1集合改变，不自动换ID，新旧映射和迁移需单独记录。
- ID只用于内部管理，`商品N_ID`始终使用真实Mercari商品ID；不得把SPU1写入成员商品ID或买家可见的省略名。

### 本轮验证证据

[Shop4 / inbox #483](https://github.com/retailpulses/inbox/issues/483)：41组、188个listing的候选CSV，按既有70组审核表中的SPU1字段精确对应，全部为单SPU1组。40组直接采用SPU1；`PP298908`在2026-11-18原始商品导出中已有10个成员，因此新4成员组采用`PP298908_02`，保留旧组。41个ID均唯一、最长13字符，与该导出中的519个现有组ID无冲突。只修改`商品グループID`，其余23列及行序保持不变；24列表头、UTF-8 BOM、成员数量/唯一性/类目一致、省略名非空且组内唯一均通过本地校验。此证据不包含空组检查、Seller预览或线上提交；多SPU1压缩算法尚无Seller实证。
